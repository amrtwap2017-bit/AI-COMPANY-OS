# Epic Catalog Management

## Overview

The Epic Catalog is the authoritative registry of all epics across the program. It provides a single source of truth for epic inventory, status, and key attributes. The catalog enables portfolio-level visibility, reporting, and governance.

## Epic Registration

### Registration Process

1. **Intake:** Epic candidates are submitted via the Epic Template by any authorized stakeholder
2. **Validation:** The Program Manager validates completeness and alignment with program objectives
3. **Registration:** Approved candidates receive a unique Epic ID and are entered into the catalog
4. **Triage:** Registered epics are assigned to the appropriate prioritization queue

### Registration Requirements

- Completed Epic Template (minimum: title, description, strategic objective, business capability)
- Identified Epic Owner
- Initial t-shirt size effort estimate
- Key stakeholder identified

## Catalog Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| Epic ID | String | Yes | Unique identifier (EPIC-{NNN}) |
| Title | String | Yes | Concise epic name |
| Program | String | Yes | Program affiliation |
| Description | Text | Yes | Epic summary |
| Strategic Objective | String | Yes | Linked objective from Program 1 |
| Business Capability | String | Yes | Linked capability from Program 1 |
| Status | Enum | Yes | Current lifecycle state |
| Priority | Enum | Yes | P0, P1, P2, or P3 |
| Business Value Score | Number | Yes | Composite value score (0-100) |
| Effort Estimate | String | Yes | T-shirt size or story point range |
| Epic Owner | String | Yes | Responsible individual |
| Dependencies | List | No | Key dependency references |
| Risk Level | Enum | Yes | High, Medium, Low |
| Target Release | String | No | Intended release |
| Progress | Percentage | Yes | % complete based on feature delivery |
| Created Date | Date | Yes | Registration date |
| Last Updated | Date | Yes | Last modification date |
| Target Close Date | Date | No | Planned completion date |
| Actual Close Date | Date | No | Actual completion date |
| Value Realized | Text | No | Post-completion value assessment |

## Catalog Reporting

### Standard Reports

- **Epic Portfolio View:** All epics grouped by status with key metrics
- **Priority Distribution:** Count and percentage by priority tier
- **Epic Aging Report:** Epics by days in current status, highlighting stalled items
- **Value vs. Effort Matrix:** Bubble chart plotting value score against effort
- **Progress Dashboard:** Status distribution with trend lines
- **Risk Heatmap:** Epics mapped by risk probability and impact

### Custom Reports

Reports can be generated by filtering on any catalog field. Common filters include:
- Epics by strategic objective
- Epics by business capability
- Epics by owner
- Epics by target release
- Epics by risk level

## Catalog Review Process

| Cadence | Review | Participants | Focus |
|---------|--------|-------------|-------|
| Weekly | Status Triage | Program Manager | New entries, status changes, blockers |
| Monthly | Catalog Health | Program Manager, Epic Owners | Data quality, stale entries, metric review |
| Quarterly | Portfolio Review | Steering Committee | Reprioritization, new epics, retirements |
| Ad-hoc | Exception Review | Program Manager | Urgent additions, escalations |

## Data Quality Standards

- All required fields must be populated within 5 business days of registration
- Status must be updated within 2 business days of any state change
- Progress must be updated at least weekly during active execution
- Stale entries (no update in 30 days) trigger automated review
- Duplicate epics are flagged and merged or rejected

## Tool Integration

The Epic Catalog integrates with:
- **Program 1 (Enterprise Blueprint)** for capability tracing
- **Feature Management** for epic decomposition tracking
- **Sprint Tracking Tools** for progress updates
- **Dependency Management** for cross-epic dependency visibility
- **Executive Dashboard** for portfolio-level reporting
