# Glossary

> Shared language for all AI agents operating within the Enterprise AI Delivery Framework.

| Term | Definition |
|------|------------|
| ADR | Architecture Decision Record — a document recording an architecture decision and its rationale |
| AI Agent | An AI-powered entity with a defined role, responsibilities, and authority within the framework |
| Architecture Baseline | The frozen set of technology and architecture decisions that constrain all implementation |
| Artifact | Any generated output: code, documentation, schema, prompt, template |
| Bounded Context | A DDD concept — the boundary within which a domain model is valid |
| Business Capability | A discrete function the system performs that delivers business value |
| C4 Model | A hierarchical modeling approach: Context, Container, Component, Code |
| Context Packet | The minimal set of information an AI agent receives to perform a task |
| DDD | Domain-Driven Design — a software development approach focusing on the domain model |
| Delivery Pipeline | The sequential stages every feature passes through from requirement to release |
| EADF | Enterprise AI Delivery Framework — Program 2 |
| Enterprise Blueprint | Program 1 — the complete enterprise architecture and business specification |
| Hotfix | An expedited delivery for production issues with reduced gates |
| LLM | Large Language Model — the underlying AI model powering agents |
| Quality Gate | A mandatory check that an artifact must pass before proceeding to the next stage |
| Schema-per-Tenant | Multi-tenancy strategy where each tenant gets its own database schema |
| Sprint Engine | The automated system that produces all sprint artifacts |
| Ubiquitous Language | A DDD concept — a shared language shared by domain experts and developers |
