# Contributing to Triangle Black

## Repository Rules

1. **No code before documentation** — Every feature requires an approved architecture decision.
2. **Traceability** — Every file must trace back to a business capability.
3. **One source of truth** — Information lives in exactly one place. Cross-reference, never duplicate.
4. **Review before merge** — All changes require review. No direct commits to main.
5. **Version control** — Every document has a version number and changelog entry.

## Document Standards

Every document must include:
- Document header (purpose, owner, version, status, dependencies)
- Business value statement
- Cross-references to related documents

## Workflow

1. Create a branch from `main`
2. Make your changes following the document standards
3. Submit a pull request with description of changes
4. Request review from relevant stakeholders
5. Merge after approval

## Quality Gates

- [ ] Business-aligned
- [ ] Technically feasible
- [ ] Internally consistent
- [ ] Cross-references correct
- [ ] No contradictions with related documents
- [ ] Reviewed against all 10 Enterprise Architecture phases (A-J)
